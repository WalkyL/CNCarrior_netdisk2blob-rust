SMB / FUSE

现象：SMB Runtime 显示 degraded，listener 就绪，但 CCBGRoot 或 rclone-backed share 挂不上。

原因：PVE/LXC guest 里缺少 /dev/fuse。这一步必须在 PVE 宿主机给容器透传，Admin 页面不能自动完成。

FUSE 可以理解成 Linux 的“用户态文件系统”接口。CCBG 的 SMB sidecar 会先用 rclone mount 把云盘内容挂成本地目录，再交给 smbd 共享出去；没有 /dev/fuse 时，445 监听可以起来，但真实 share 不能挂载成功。

# PVE 宿主机 shell；把 <CTID> 改成实际容器 ID
pct stop <CTID>
cat >> /etc/pve/lxc/<CTID>.conf <<'EOF'
features: fuse=1,nesting=1
lxc.cgroup2.devices.allow: c 10:229 rwm
lxc.mount.entry: /dev/fuse dev/fuse none bind,create=file,optional 0 0
EOF
pct start <CTID>
# CCBG 容器内验收
ls -l /dev/fuse
systemctl start ccbg-smb-sidecar-sync.service
python3 /opt/ccbg/scripts/ccbg-smb-sidecar.py status

96 MiB LXC + 加密

我们公开做过一轮 96 MiB Debian LXC 的低内存验证：同时运行 gatewayd、SMB sidecar 和 FUSE 读环，10 分钟明文 soak 为 269/269 成功。

同一宿主上，8 MiB 对象、4 并发的 10 分钟加密 soak 为 216/216 成功，另外 16 MiB spooled 加密 smoke 也 4/4 成功。

对比同配置明文路径，加密后的网关 RSS 增幅不大，主要代价是时延更高。结论是：96 MiB 可以做验证，但不应视为舒适生产预算；日常仍建议 256 MiB+，并把 CCBG_DATA_PLANE_MAX_IN_FLIGHT 控制在 2~4。
