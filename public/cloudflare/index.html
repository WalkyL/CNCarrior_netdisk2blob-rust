把运营商云盘转换为本地 S3 块存储

在家里的电脑、NAS 或小主机上运行 CCBG，把联通、电信、移动云盘变成局域网里的统一存储。 Windows、macOS、Linux 和常见备份工具可以通过 S3 或 SMB 访问；登录、共享、健康状态和同步规则都在网页里管理。

推荐安装 PVE LXC / Linux 
curl -fsSLO https://carrier-disk-gateway.agi2030.online/downloads/latest/ccbg-lxc-package.tar.gz
tar --no-same-owner -xzf ccbg-lxc-package.tar.gz

61080 是 S3 API，61081 是 Admin；只有 Linux / LXC 的 SMB profile 会先监听 445。进 Admin 加一个 SMB 用户即可自动生成默认 root 共享；PVE/LXC 真正挂载共享前还需暴露 /dev/fuse 全部平台

运行模型

控制面和数据面分离；浏览器自动化、运营商会话和对象网关都保持可替换边界。

本地 S3 数据面

面向应用、rclone、桌面挂载和 Agent，默认以局域网/回环部署为边界。

Admin 控制面

在同一个局域网控制面里管理登录、健康状态、复制策略和桌面挂载入口。

低内存策略

大对象走流式和有界 spool；平台 profile 控制并发、日志和缓存上限。

低内存实测

公开摘要只保留宿主级别、对象尺寸、时长和区间数据，不暴露内网地址、凭据或测试前缀。

96 MiB LXC + 明文

公开实验环境在 96 MiB Debian LXC 上跑过 10 分钟明文 soak：8 MiB 对象、4 并发、同时保留 SMB sidecar 与 FUSE 读环，结果是 269/269 成功。

这轮里 gateway RSS 大致落在 p95 64.3 MiB、max 74.7 MiB；说明低内存环境可以验证功能，但余量并不宽。

96 MiB LXC + 加密

同一宿主又做过 10 分钟加密 soak：8 MiB 对象、4 并发、216/216 成功；另有 16 MiB spooled 加密 smoke，4/4 成功。

加密后 gateway RSS 大致落在 p95 65.9 MiB、max 75.8 MiB，内存增幅有限，但时延高于明文。

公开结论

CCBG 的加密路径已经过低内存验证；主要成本是时延，不是成倍放大的 RSS。96 MiB 适合实验和验收，不建议作为舒适生产预算。

日常运行仍建议 256 MiB+，并把 CCBG_DATA_PLANE_MAX_IN_FLIGHT 控制在 2~4。
