## 1. Stale Primary Fencing ✅

**目标**: primary provider auth 失效后，自动降级到健康 write target，避免请求继续撞 502。

**实施**:
- put_object 路径: 若 primary 状态为 `reauth_required` 且有健康 write target，跳过 primary 直接写 write target
- execute_put_upload 中 fencing 判断: 在 `persist_object_home_provider` 前检查 lease 状态
- 后端: 新增 `is_primary_stale(state, provider) -> bool` 函数，查询 lease 状态
- 告警: 当 primary 被 fencing 时产生 `primary_fenced` 告警

**验收标准**:
- [x] `is_primary_stale` 在 lease `reauth_required` 时返回 true
- [ ] put 路径在 primary stale 时优先写 write target
- [x] 新增 `primary_fenced` 告警在 Admin 可见
- [x] 测试: `cargo test -p gatewayd primary_fencing_`
- [ ] 测试: lease 恢复正常后 fencing 自动解除

**注意**: 验收标准第 2 条（put 路径自动降级）和第 5 条（自动解除）尚未实现。当前仅完成后端 fencing 检测和告警层。

## 2. Lease first_failure_at ✅

**目标**: 记录首次 auth 失败时间，避免 reboot 后 `last_verified_at` 覆盖掉事故定界信息。

**实施**:
- 在 `ProviderCredentialLeaseRecord` 中新增 `first_failure_at_unix_ms: Option<u64>`
- 在 `maybe_probe_provider_credential_lease` 中: 当状态从 active 变为 reauth_required 时记录 first_failure_at
- 在 `payload` 中暴露 `first_failure_at_unix_ms`
- 持久化: 写入 lease.json 文件

**验收标准**:
- [x] lease.json 中含 `first_failure_at_unix_ms`
- [x] 首次探测到 reauth_required 时记录，后续不覆盖
- [x] 状态恢复 active 后不清除该字段
- [x] 测试: `cargo test -p gatewayd first_failure_at_`
