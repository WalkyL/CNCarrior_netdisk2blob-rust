# ADR-002: 历史对象收敛必须显式执行，并受容量与本地缓冲预算约束

## 状态
Accepted

Implementation in progress

## 日期
2026-05-25

## 背景

当前网关已经支持:

- 新写入按应用和内容策略决定副本目标
- 持久化 home provider / 逻辑对象元数据
- 对历史对象给出“如果显式收敛，会发生什么”的预览

但用户实际会遇到一类高风险场景:

1. 先在 `A` 云盘写了大量历史对象。
2. 后来内容策略改变，要求:
   - 给这些旧对象补 `B` 或 `C` 副本
   - 把 home provider 从 `A` 迁到 `B`
   - 把明文改成加密写入
   - 切换加密 profile
   - 取消加密

如果系统对历史对象做隐式搬迁，会带来几个问题:

- 用户不知道什么时候发生了真实数据移动
- 目标云盘可能空间不足
- 加密后落盘体积可能大于明文体积
- 同 provider 重写时可能需要临时对象，峰值空间远大于最终空间
- 本地宿主可能因为 spool 空间不足而失败
- 如果删除旧副本过早，可能导致数据丢失

## 决策

### 1. 历史对象收敛默认不自动发生

内容策略变化默认只影响:

- 新写入
- 覆盖写

历史对象不会自动:

- 补新副本
- 删旧副本
- 切换 home provider
- 加密重写
- 解密重写
- 切换加密 profile

这些动作必须:

1. 先预览
2. 再显式执行
3. 记录审计信息

### 2. 执行前必须做容量与缓冲预检

显式收敛执行前必须同时计算:

- 目标 provider 最终所需空间
- 目标 provider 峰值所需空间
- 本地 spool 峰值所需空间

其中:

- 加密迁移必须按 `stored_size_target` 判断，不得按明文大小判断
- 同 provider、同 key 的重写必须按两阶段路径的峰值空间判断
- 本地 spool 预算不足时也必须阻断

### 3. 容量未知时默认阻断

如果任一关键空间事实未知:

- 目标 provider 无法返回可用容量
- 本地 spool 剩余空间无法判断
- 目标写路径是否需要整对象回放无法判断

则默认阻断执行，而不是乐观放行。

### 4. 删除旧副本必须后置

显式收敛的一般顺序固定为:

1. 写入新目标
2. 校验新目标
3. 更新 placement / 保护计划 / 加密元数据
4. 删除旧副本

如果新目标写失败:

- 不更新 placement
- 不更新 home provider
- 不删除旧副本

### 5. 同 provider、同 key 的重写必须使用临时对象

对:

- 明文 -> 加密
- 加密 -> 明文
- profile A -> profile B

如果目标还是同一个 provider、同一个 key，必须走临时对象两阶段路径，不能原地覆盖。

## 后果

### 正面影响

- 避免静默数据迁移
- 避免用户在不知情时丢数据
- 能把容量不足和本地 spool 风险前置到预览阶段
- 更适合 `N100`、`arm64`、软路由等资源敏感宿主

### 负面影响

- 历史对象不会因为策略变化自动“跟上当前策略”
- 用户需要手动触发显式收敛
- 执行器实现比“直接复制再删旧”更复杂
- Admin 必须把阻断原因讲清楚

## 直接要求

后续执行路径落地时，Admin 和后端至少必须支持:

- 显示当前 / 目标 home provider
- 显示当前 / 目标加密状态与 profile
- 显示新增 / 删除副本集合
- 显示目标 provider 最终空间
- 显示目标 provider 峰值空间
- 显示本地 spool 预算上界
- 在阻断时给出明确原因
